# Company Platform

A platform that builds platforms.

## Structure

```
company-platform/
│
├── CLAUDE.md                          ← rules index, loaded every session
│
├── .claude/
│   ├── rules/                         ← granular rule modules (read by skills)
│   │   ├── security.md                  secrets, IAM, input validation
│   │   ├── naming.md                    conventions for everything
│   │   ├── aws.md                       Lambda defaults, Terraform patterns, regions
│   │   ├── testing.md                   coverage floors, what/what-not to mock
│   │   └── design-system.md             tokens, components, a11y
│   │
│   └── commands/                      ← slash commands (skills)
│       ├── lambda.md    → /lambda       scaffold a production Lambda
│       ├── component.md → /component    scaffold a design system component
│       ├── event.md     → /event        define an event bus event + schema
│       ├── diagram.md   → /diagram      generate/update architecture diagrams
│       └── onboard.md   → /onboard      personalised new-joiner guide
│
├── architecture/
│   └── system-map.md                  ← Mermaid diagrams — INPUT to Claude
│                                        Claude reads these before any change
│                                        Claude updates these when things change
│
├── platforms/
│   ├── infrastructure/
│   │   └── lambdas/<name>/            ← generated by /lambda
│   │       ├── src/handler.ts
│   │       ├── src/types.ts
│   │       └── infra/stack.ts
│   │
│   ├── design-system/
│   │   ├── tokens/index.ts            ← source of truth for tokens
│   │   └── components/<Name>/         ← generated by /component

│   │       └── Component.stories.tsx
│   │
│   └── data-platform/

│           └── consumer.ts
│
```

## Commands — sample usage

### `/lambda` — scaffold a production Lambda

```bash
# API-triggered Lambda (default)
/lambda user-profile-get-api

# Event-triggered Lambda (listens to EventBridge)
/lambda payment-process-event --trigger event

# Scheduled Lambda (runs on a cron)
/lambda report-generate-scheduled --trigger scheduled
```

Generates: `src/handler.ts` (Zod-validated), `src/types.ts`, `infra/main.tf` (Terraform with IAM, DLQ, X-Ray, tags).

---

### `/component` — scaffold a design system component

```bash
# Basic component
/component UserCard

# With a variant hint
/component PaymentForm --variant modal

# Alert-style component
/component NotificationBanner --type alert
```

Generates: `Component.tsx` (tokens only, no raw values), `Component.test.tsx` (render + interaction + axe), `Component.stories.tsx` (all variants).

---

### `/event` — define an event bus event

```bash
/event user.profile.updated
/event payment.invoice.created
/event order.item.shipped
```

Generates: `schema.ts` (Zod contract), `publisher.ts` (typed helper), `consumer.ts` (EventBridge rule stub).
Schema is marked as a breaking-change boundary — changes require a PRD.

---

### `/diagram` — generate or update architecture diagrams

```bash
# Generate a new flow diagram from code
/diagram flow "checkout process"

# Regenerate the full system map from current source
/diagram system

# Read current diagram + git diff → update in place
/diagram update
```

Diagrams saved to `architecture/`. The one exception to immutability — updated in place, not versioned.

---

### `/onboard` — personalised new joiner guide

```bash
/onboard "Sarah — senior frontend, strong React, new to AWS"
/onboard "Miguel — backend engineer, knows Node, new to the company"
```

Generates: `artifacts/onboarding-<name>-YYYY-MM-DD.md` — tailored to their background, references actual file paths, commands, and rule files in this repo.

## Mermaid usage

| Mode       | Example                                      | How                                                                            |
| ---------- | -------------------------------------------- | ------------------------------------------------------------------------------ |
| **Input**  | `architecture/system-map.md`                 | Claude reads it before generating code to understand where things fit          |
| **Output** | Claude generates a flow diagram inside a PRD | Claude writes the Mermaid block as part of its output                          |
| **Both**   | `/diagram update`                            | Claude reads the current diagram + git diff, updates the diagram to match code |

Mermaid diagrams in `architecture/` are **living documentation**.
They are the one exception to the artifact immutability rule — they get updated in place.
Everything else Claude produces is immutable and versioned by date.

## The platform-of-platforms idea

```
This repo (company-platform)
    ↓ provides
Lambda Factory  →  any team runs /lambda to get a production-ready function
Design System   →  any team runs /component to get a compliant UI component
Event Bus       →  any team runs /event to define a typed, contracted event
    ↓ those teams build
Customer Portal, Admin Dashboard, Mobile App, Data Pipelines...
    ↓ those products run
/lambda, /component, /event from THIS repo
    ↓ so changes to rules here propagate everywhere
Update .claude/rules/aws.md → every future Lambda scaffolded by any team
gets the new standard automatically
```

The rules in `.claude/rules/` are the governance layer.
The skills in `.claude/commands/` are the delivery layer.
The architecture diagrams are the knowledge layer.
CLAUDE.md is the constitution.
