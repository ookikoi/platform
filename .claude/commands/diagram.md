# /diagram

Generate or update a Mermaid diagram. Can be used as input, output, or both.

## Usage

```
/diagram system          → regenerate architecture/system-map.md from current code
/diagram flow "checkout" → generate a new flow diagram for a named process
/diagram update          → read existing diagram + diff, update to reflect changes
```

## The three modes

### Output — generate a diagram from code

```
/diagram flow "checkout process"
```

Claude reads the relevant source files and produces a Mermaid flowchart
showing the actual current behaviour. Saved to `architecture/<name>.md`.

### Input — Claude reads diagram to understand system before acting

This happens automatically when you run /lambda, /component, /api.
Claude reads `architecture/system-map.md` before generating anything
so it understands where the new piece fits.

### Both — update an existing diagram after a change

```
/diagram update
```

Claude reads the current diagram + the git diff, identifies what changed,
updates the diagram to match. Keeps docs in sync with code automatically.

## Prompt sent to Claude

Mode is determined by the argument:

- `system` → read all src/ files, regenerate architecture/system-map.md
- `flow "<process>"` → read relevant files for that process, generate new diagram
- `update` → read architecture/system-map.md + git diff, update diagram

Always save output to `architecture/` with a descriptive filename.
Add a comment at the top: `<!-- Generated by /diagram YYYY-MM-DD -->`.
If updating an existing diagram, replace it in-place (this is the one exception to the artifact immutability rule — diagrams are living docs).
